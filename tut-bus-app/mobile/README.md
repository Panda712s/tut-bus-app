# TUT Bus App — Mobile (Flutter)

This folder contains the complete Dart application: `pubspec.yaml` and everything under `lib/` (models, services, state, screens, widgets) for both the **student** and **driver** flows described in the project documentation.

## Why you need to run `flutter create .` once

Flutter projects need platform-specific native scaffolding — `android/`, `ios/`, Gradle files, an Xcode project, etc. — that is generated by the Flutter SDK's toolchain (not hand-written). The environment this app was built in does not have the Flutter SDK installed, so that generated boilerplate isn't included here. This is the standard way to layer a hand-written Dart app onto fresh native scaffolding, and it takes two minutes.

**Setup:**

```bash
cd mobile
flutter create --org za.ac.tut --project-name tut_bus_app .
flutter pub get
```

`flutter create .` will not overwrite `lib/main.dart` or `pubspec.yaml` if it detects they already exist in a meaningful way — but to be safe, **do this in a clean checkout before you've made your own edits**, and re-check `pubspec.yaml` afterwards to make sure your dependencies list (above) is still intact. If it gets reset, just re-copy the `dependencies:` block from this repo's `pubspec.yaml`.

## Required manual configuration

### 1. Google Maps API key

The doc recommends Google Maps SDK for live tracking, so that's what `live_map_tab.dart` uses (`google_maps_flutter`). You need a Google Cloud project with the **Maps SDK for Android** and **Maps SDK for iOS** enabled, and an API key.

**Android** — add to `android/app/src/main/AndroidManifest.xml`, inside the `<application>` tag:

```xml
<meta-data
    android:name="com.google.android.geo.API_KEY"
    android:value="YOUR_GOOGLE_MAPS_API_KEY" />
```

Also add these permissions inside `<manifest>` (above `<application>`):

```xml
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />
<uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />
```

**iOS** — add to `ios/Runner/AppDelegate.swift` (inside `application(_:didFinishLaunchingWithOptions:)`, before `return super...`):

```swift
GMSServices.provideAPIKey("YOUR_GOOGLE_MAPS_API_KEY")
```

(and `import GoogleMaps` at the top of the file). Also add to `ios/Runner/Info.plist`:

```xml
<key>NSLocationWhenInUseUsageDescription</key>
<string>The driver app needs your location to share your bus's live position with students.</string>
<key>NSLocationAlwaysAndWhenInUseUsageDescription</key>
<string>The driver app needs your location to share your bus's live position with students, including while backgrounded during a trip.</string>
```

### 2. Point the app at your backend

`lib/config/api_config.dart` reads `API_BASE_URL` and `SOCKET_BASE_URL` from `--dart-define`, defaulting to `http://10.0.2.2:3000` (the Android emulator's alias for your host machine's `localhost`). Run with:

```bash
flutter run \
  --dart-define=API_BASE_URL=http://10.0.2.2:3000/api/v1 \
  --dart-define=SOCKET_BASE_URL=http://10.0.2.2:3000 \
  --dart-define=GOOGLE_MAPS_API_KEY=YOUR_KEY
```

- iOS simulator: use `http://localhost:3000/api/v1`
- Physical device: use your computer's LAN IP, e.g. `http://192.168.1.50:3000/api/v1`

### 3. Firebase (push notifications)

The doc specifies Firebase Cloud Messaging. The backend already has an FCM stub (`backend/src/notifications/fcm.service.ts`) and in-app/WebSocket notifications work out of the box without Firebase. To add real push notifications:

1. Create a Firebase project, add Android/iOS apps, download `google-services.json` / `GoogleService-Info.plist` into the generated native folders.
2. Add `firebase_core` and `firebase_messaging` to `pubspec.yaml`.
3. Register the device token with the backend (add a `deviceToken` field to `Student`/`Driver` and a small endpoint to save it) and wire it into `FcmService.send()`.

This is intentionally left as a follow-up since it requires your own Firebase project credentials.

## App structure

```
lib/
  config/          API base URL, Google Maps key
  models/          Plain Dart data classes mirroring the backend's DTOs
  services/        REST client, socket clients, repositories per domain
  state/           AuthState (Provider) - who's logged in, as which role
  screens/
    auth/          Role select, student login/register/OTP/forgot-password, driver login
    student/       Home, Live Map, Routes (+ detail, schedules, favourites), Notifications, Profile,
                    Trip history, Feedback, QR boarding
    driver/        Trip dashboard (start/pause/resume/end, live GPS streaming, passenger count),
                    incident reporting, notifications, profile
  widgets/         Shared UI (buttons, badges, loading/error/empty states)
```

Auth tokens are stored with `shared_preferences` for simplicity; swap `lib/services/token_storage.dart` for `flutter_secure_storage` before shipping to production.
